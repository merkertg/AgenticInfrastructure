## Реализованная граница этапа 03

Добавлены PostgreSQL-схема из десяти таблиц, миграция Alembic `0001_initial`
и адаптер `MemoryStore`. Доверенный Python-код читает сохранённую версию
и добавляет следующую версию существующего документа. Перед операцией адаптер
блокирует строку компании, загружает текущие объекты и права из БД и применяет
прежнюю функцию `evaluate_access()`.

Запись версии, запись аудита и результат запроса для идемпотентности
фиксируются одной транзакцией `READ COMMITTED`. Ошибка вставки аудита откатывает
всю операцию и не возвращает успешный результат. Повтор того же запроса
возвращает ранее созданную версию после новой проверки прав; изменённый
payload под тем же ключом и устаревший ожидаемый номер дают конфликт.
Аудит содержит метаданные попытки и результат, но не текст и не источник документа.

HTTP-приложение не менялось: только `/health` и документация API. Переданные
идентификаторы сотрудника и агента остаются входными данными доверенного кода,
а не подтверждённой личностью. Начальные записи создаёт вымышленная лаборатория.

## Что ещё отсутствует

Нет подтверждённой сервером личности, HTTP API памяти, общего приёма документов,
администрирования прав, поиска, LLM, корпоративного коннектора и контейнерного
выпуска. Владелец БД может напрямую изменить версии и аудит: история
не защищена от администратора PostgreSQL. Блокировка строки компании
упорядочивает операции этого адаптера, но не измерялась под нагрузкой.
Временный локальный кластер не является развёрнутым сервисом.
Следующий этап — подтверждённая личность, делегирование и ограниченный API памяти.
