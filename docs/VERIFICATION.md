## Реализованная граница этапа 02

Добавлены неизменяемые Python-модели компании, проекта, сотрудника, агента,
делегирования, документа, версии, разрешения, запроса и решения о доступе.
`evaluate_access()` проверяет явный снимок объектов без внешних обращений.
Для разрешения нужны действующие права сотрудника на документ и делегированное
агенту действие в той же компании и проекте. Чтение и запись независимы.
Отсутствие данных или прав, отзыв, несовпадение области, владельца агента
или версии приводят к отказу с кодом причины.

`make_audit_event()` создаёт описание попытки авторизации с явно переданным
временем, нормализованным в UTC. Событие содержит метаданные запроса и решения,
но не текст документа. Оно не сохраняется и не доказывает выполнение операции.
Офлайн-демо воспроизводит восемь вымышленных сценариев.

Идентификатор сотрудника остаётся входными данными, а не доказательством
личности. Снимок объектов передаёт вызывающий код; подтверждение его
происхождения, актуальности и конкурентных изменений ещё не реализовано.
Проверка `WRITE` относится к существующему документу/версии и не изменяет память.

## Офлайн-сценарии

| Сценарий | Решение | Причина |
| --- | --- | --- |
| Финансовый помощник, разрешённое чтение | Разрешено | `allowed` |
| Инженерный помощник, финансовый документ | Отказ | `project_mismatch` |
| Документ другой компании | Отказ | `company_mismatch` |
| Нет права сотрудника | Отказ | `employee_permission_missing` |
| Делегирование отозвано | Отказ | `delegation_unavailable` |
| Запись при праве сотрудника только на чтение | Отказ | `employee_permission_missing` |
| Версия другого документа | Отказ | `version_mismatch` |
| Действие не делегировано | Отказ | `action_not_delegated` |

Результаты — решения по переданным объектам; данные не читаются из хранилища
и не возвращаются клиенту. Время в демо фиксировано, чтобы вывод повторялся.

## Регрессия HTTP и предыдущий этап

HTTP-приложение не менялось: только `GET /health` и автоматически созданная
документация. Контракт повторно проверен TestClient в составе 139 тестов.
`GET /memory`, `GET /agents` и `/` возвращают `404`, `POST /health` — `405`.

Реальный сетевой запуск Uvicorn выполнен на этапе 01 и повторно на этапе 02
не выполнялся. Тогда `/health`, `/docs`, `/redoc`, `/openapi.json` вернули
`200`, будущие маршруты — `404`; процесс остановлен. Проверка HTML не являлась
визуальной проверкой браузера и доступности ресурсов CDN.

Исходная локальная проверка этапа 01: 34 теста, Ruff, strict mypy по восьми
файлам, 56 локальных ссылок в 14 Markdown-файлах и проверка lock/пробелов.
При разрешении зависимостей ограниченная среда запрещала DNS/PyPI, а при
HTTP-запуске — локальный bind. После разрешённого запуска обе проверки прошли.
Исторические машинные результаты сохранены в разделе `previous_stages`.

## Что ещё отсутствует

Нет постоянного хранилища документов и версий, миграций, аутентификации,
авторизованного HTTP API памяти, записи аудита, транзакций, поиска, LLM,
корпоративного коннектора и контейнерного выпуска. Скрытие текста из `repr`
не является контролем доступа: сам объект версии содержит вымышленный текст.
Успешное офлайн-решение не доказывает безопасность корпоративного сервиса.
