# Этап 01. Основа сервиса корпоративной памяти

[README](../README.md) · [Дорожная карта](ROADMAP.md) · [Проверки](VERIFICATION.md)

## Что строим

Будущий сервис будет давать агентам сотрудников доступ к общей корпоративной
памяти. Например, агент инженера сможет прочитать инструкцию своего проекта,
но не закрытый финансовый документ. Два агента сотрудников с одинаковыми правами
смогут использовать один разрешённый источник вместо отдельных копий знаний.
Сервис будет проверять права и сохранять историю обращений.

Это целевое поведение следующих этапов. Сейчас создан только запускаемый
HTTP-сервис. Он отвечает на проверочный запрос и предоставляет документацию API.
Документов, пользователей, авторизации, истории действий и вызовов модели в нём
пока нет. Такая граница позволяет сначала разобраться с запуском и проверками,
а затем добавлять правила доступа небольшими проверяемыми шагами.

## Результат этапа

- Python 3.12 и зависимости, зафиксированные в `uv.lock`.
- FastAPI-приложение с фабрикой `create_app()`.
- Настройки, проверяемые при запуске.
- `GET /health` со строгой моделью ответа.
- Автоматические тесты, Ruff, strict mypy и проверка локальных ссылок.
- Конфигурация GitHub Actions и инструкция запуска.

Готовность этапа означает успешные локальные проверки из
[отчёта](VERIFICATION.md). Наличие файла GitHub Actions само по себе не означает,
что удалённая проверка прошла. Полное решение задания получится после реализации
последующих этапов.

## 1. Подготовить окружение

Откройте терминал в корне `AgenticInfrastructure`, где лежит `pyproject.toml`.
Нужен менеджер [uv](https://docs.astral.sh/uv/getting-started/installation/).

```bash
uv --version
uv sync --locked
```

`uv sync` создаёт локальное виртуальное окружение `.venv` и устанавливает
зависимости. `.venv` отделяет пакеты проекта от системного Python и других
проектов. Номер Python записан в `.python-version`, допустимый диапазон —
в `pyproject.toml`.

`pyproject.toml` описывает проект, допустимые версии библиотек и правила
инструментов проверки. `uv.lock` хранит точный результат выбора версий, включая
зависимости библиотек. `--locked` запрещает незаметно переписать этот результат:
если описание и lock расходятся, команда сообщает об ошибке. См.
[документацию uv](https://docs.astral.sh/uv/concepts/projects/sync/).

Обычные команды запускайте с `--locked`. Обновление зависимостей — отдельное
осознанное изменение с повторными проверками. Первоначальный выбор использует
дату отсечения релизов `2026-10-10T00:00:00Z`, то есть две недели до начала этапа.
Эта задержка не заменяет проверку уязвимостей.

## 3. Настроить приложение

Можно работать со стандартными значениями без `.env`. Для явной локальной
настройки скопируйте пример:

```bash
cp -n .env.example .env
```

Содержимое:

```dotenv
APP_NAME=agentic-infrastructure
APP_ENV=development
APP_DEBUG=false
```

`-n` сохраняет существующий `.env`, если вы уже настроили его.

`APP_NAME` определяет заголовок API и поле `service` в ответе. Пробелы по краям
удаляются, пустое имя отклоняется. `APP_ENV` допускает только `development`,
`test`, `production`. Ошибка вроде `prodution` приведёт к отказу запуска вместо
незаметной опечатки. `APP_DEBUG` управляет режимом отладки; стандартно он выключен.
Метка `production` пока не подключает авторизацию или защиту корпоративных данных.

В `Settings` используется Pydantic Settings. Приоритет источников:

1. Явные аргументы `Settings(...)`, например в тесте.
2. Переменные текущего процесса.
3. Локальный файл `.env`.
4. Стандартные значения модели.

Подробности механизма — в
[официальной документации](https://docs.pydantic.dev/latest/concepts/pydantic_settings/).
Например, `APP_NAME=demo uv run --locked uvicorn app.main:app --port 8005`
переопределит имя только для этого запуска. `.env` остаётся локальным и
исключён из Git через `.gitignore`.

`get_settings()` использует `lru_cache`: после первого чтения процесс повторно
использует тот же объект. Поэтому после изменения настроек перезапустите сервер.
Тесты очищают кеш перед проверкой и после неё.

## 4. Запустить сервер

```bash
uv run --locked uvicorn app.main:app --reload --host 127.0.0.1 --port 8005
```

`uv run` выполняет команду в окружении проекта. Uvicorn принимает HTTP-запросы
и передаёт их приложению. `app.main:app` означает: импортировать модуль
`app/main.py` и взять из него объект `app`. `--reload` перезапускает сервер при
изменении файлов; это удобство локальной разработки. `127.0.0.1` ограничивает
прослушивание текущим компьютером. Порт `8005` выбран для параллельной работы
с соседними учебными проектами.

Оставьте сервер в первом терминале. Во втором выполните:

```bash
curl -i http://127.0.0.1:8005/health
```

Ожидается HTTP `200` и тело:

```json
{"status":"ok","service":"agentic-infrastructure"}
```

Проверка `/health` отвечает только на вопрос, может ли приложение вернуть ответ.
Она не проверяет готовность памяти, прав доступа или истории действий: этих
частей ещё нет. Такая проверка называется liveness.

Откройте в браузере `http://127.0.0.1:8005/docs`. Swagger UI показывает
описание API и позволяет выполнить `GET /health` через `Try it out` → `Execute`.
`/redoc` даёт альтернативную страницу описания, `/openapi.json` — машинное
описание маршрутов и моделей. Страницы интерфейсов используют ресурсы CDN:
без доступа к ним HTML может открыться, а интерфейс — не загрузиться.

У приложения нет главной страницы: запрос `/` вернёт `404`. `/memory` и `/agents`
также вернут `404`; это ожидаемая граница этапа. `POST /health` вернёт `405`,
поскольку поддерживается только метод `GET`. Остановка сервера — `Ctrl+C`.

## 5. Проследить путь запроса по коду

```text
curl / браузер
      ↓ HTTP GET /health
Uvicorn
      ↓ вызов ASGI-приложения
FastAPI: объект app, созданный create_app()
      ↓ выбор маршрута
health()
      ↓ HealthResponse(status="ok", service=имя_сервиса)
JSON и HTTP 200
```

`create_app()` — фабрика: функция создаёт и возвращает новое приложение.
Без аргумента она берёт настройки через `get_settings()`. В тесте можно передать
свой объект `Settings`, чтобы проверить поведение без изменения других
экземпляров приложения. Настройки сохраняются в `application.state.settings`.

Декоратор `@application.get(...)` связывает HTTP-метод и путь с функцией
`health()`. `response_model=HealthResponse` описывает контракт ответа.
У модели `status` допускает только строку `ok`, а `service` должен быть строкой.
Строгий режим запрещает преобразовать число в строку; `extra="forbid"`
отклоняет посторонние поля. По этой модели FastAPI строит OpenAPI-схему.

## 6. Выполнить проверки

```bash
uv run --locked pytest
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy app tests scripts
uv run --locked python scripts/check_docs.py
uv lock --check --offline
git diff --check
```

`pytest` проверяет наблюдаемое поведение: контракт ответа, отсутствие будущих
маршрутов, настройки и независимость приложений. `TestClient` вызывает
ASGI-приложение напрямую, поэтому тестам не нужен отдельный Uvicorn или открытый
порт. Подход описан в [документации FastAPI](https://fastapi.tiangolo.com/tutorial/testing/).
Реальный сетевой запуск проверяется отдельно.

Ruff ищет ошибки стиля и импортов, затем проверяет форматирование. Mypy в строгом
режиме проверяет согласованность типов. Скрипт документации ищет сломанные
локальные ссылки; внешние адреса и существование якорей он не проверяет.
`uv lock --check --offline` проверяет согласованность lock без сети.
`git diff --check` ищет ошибки пробелов в изменениях Git.

Тесты переходят во временную папку, убирают переменные `APP_*` и сбрасывают кеш
настроек. Поэтому личный `.env` разработчика не должен менять их результат.
Они не используют корпоративные документы, внешние сервисы или ключи моделей.

## Типичные ошибки

| Симптом | Что проверить |
| --- | --- |
| `uv: command not found` | Установлен ли uv и доступен ли он через `PATH` |
| `No module named app` | Запущена ли команда из корня репозитория |
| `Address already in use` | Не занят ли порт `8005`; выберите другой `--port` |
| Ошибка валидации настроек | Имя не пустое, `APP_ENV` написан точно, debug — boolean |
| После изменения `.env` старый ответ | Перезапустите сервер: настройки кешируются |
| `404` для `/` или `/memory` | На этом этапе это ожидается; используйте `/health` |
| Не загружается Swagger UI | Проверьте доступ браузера к CDN; отдельно откройте `/openapi.json` |
| Ошибка записи кеша uv | Задайте доступный `UV_CACHE_DIR`, как в quickstart |
| Ошибка DNS/PyPI | Проверьте доступ к сети; это не ошибка маршрута `/health` |
| Окружение запрещает локальный сокет | Укажите ограничение отдельно от результата TestClient |
